# ProveIt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Static React site serving a YAML-defined bank of ~300 proof problems with KaTeX, progress tracking, 4 themes × 2 fonts.

**Architecture:** `content/*.yaml` is loaded at build time through `import.meta.glob` + a tiny Vite YAML plugin; `scripts/check.mjs` validates content (schema, ids, refs, KaTeX parse) and gates `npm run build`. React SPA with react-router; state in localStorage.

**Tech Stack:** Vite, React 18 (JSX), react-router-dom, katex, marked, js-yaml, wrangler (deploy).

**Spec:** `docs/superpowers/specs/2026-11-24-proveit-design.md`

## Global Constraints
- Adding problems/topics requires no code changes.
- Plain CSS, all values as custom properties on `:root` / `[data-theme]`.
- Terminal font mode lowercases UI chrome only (`.ui` class), never `.prose` content.
- Footer disclaimer: not affiliated with the University of Sydney.
- README minimal and lowkey.

## Review Focus
- Malformed LaTeX in YAML → check fails with file + id, build blocked.
- Duplicate ids across files → check fails.
- `related` pointing to missing id → check fails.
- Corrupt/foreign JSON on progress import → rejected with a message, existing progress untouched.
- Unknown `/p/:id` → "not found" page, not a crash.
